# Suno Music Advisor — 技术架构说明

## 一、定位

将用户的音乐创作意图（情绪描述 / 流派选择 / 参考歌曲）转化为 Suno AI 可直接使用的高质量 prompt。

核心价值：**让不懂音乐制作的人也能精准控制 Suno 的输出风格。**

## 四、核心设计决策

### 1. 为什么要分级搜索而不是每首歌都全搜？

| | 全搜索 | 分级搜索 |
|---|--------|---------|
| 热门歌曲 | 5 次搜索，大部分确认已知信息 | 2 次搜索，效率提升 60% |
| 冷门歌曲 | 5 次搜索 | 3-5 次搜索（同） |
| Prompt 质量差异 | 基线 | 热门歌曲 < 5% 差异 |

对热门歌曲，LLM 训练数据已包含充分的音乐知识，搜索只需验证 BPM/Key 精确值。

### 2. 为什么要搜 Suno 社区 prompt？

音乐分析术语 ≠ Suno 有效标签。例如：
- 乐评说"唢呐" → Suno 标签 `suona` 可用但不稳定 → 社区建议加 `Chinese double-reed`
- 乐评说"bitpop 节拍" → Suno 标签 `bitpop` 已验证 ✅
- 乐评说"talk-singing" → Suno 无此标签 → 社区用 `rhythmic spoken vocals`

**所有置信度级别都必须做 Suno 社区搜索**，因为"认识歌曲"不等于"知道 Suno 有效标签"。

### 3. 为什么用 14 维度而不是 8 维度？

| 分析维度 | 8 维度（基础） | +6 精细维度 |
|---------|--------------|------------|
| 示例 | "Trap, 140 BPM, 唢呐" | + "syncopated rhythm, dry tight mix, verse-driven build" |
| Suno 效果 | 流派大方向对，细节随机 | 节奏型/空间感/动态也被控制 |

精细维度直接写入 prompt 的 Line 2-4，让 Suno 在更多维度上贴近参考歌曲。

### 4. 为什么 prompt 中不指定性别？

不写 `male vocals` / `female vocals`，让 Suno 自由选择，避免与用户实际需求冲突。

### 5. Feature Flags 设计

可选功能默认关闭，用户明确要求时才启用，避免过度复杂化流程。

当前 Flags：
- `triangulation`（三角定位）：❌ OFF — 搜索相似歌曲交叉验证

预留 Flags（未实现）：
- `dimension-control`（维度调节）：用户主动指定调节哪个维度生成变体

## 六、局限性

1. **Suno 标签体系不公开** — 社区经验是最佳信息源，但不是官方文档
2. **Web 搜索依赖** — Tunebat 等站点可能被反爬（403），需要降级策略
3. **精细维度部分靠推断** — 如节奏型、空间感，搜索结果未必明确提及
4. **Suno 生成质量不可控** — 即使 prompt 完美，Suno 输出仍有随机性
5. **Reference 文件使用率低** — Mode 5 中主要靠搜索，reference 仅在搜索失败时兜底
