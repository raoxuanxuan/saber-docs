### 内存与光学交叉点上的技术

各路半导体专家已经反复讲过"内存是瓶颈"，这件事大多数人已经知道了。但那个昂贵的内存实际上被利用了多少？微软 Azure 的研究表明，服务器上安装的 DRAM 中最多有 **30%** 处于"搁浅"状态——已经分配，实际上没人用，但又没法分给其他服务器。服务器成本中占比最大的资源，装上就有将近三分之一被浪费。

能解决这个问题的技术叫做 **CXL（Compute Express Link）**——一种将 CPU、GPU、加速器等所有计算单元与内存进行 cache-coherent（缓存一致性）连接的开放标准互连。它能将内存从服务器插槽中解放出来，实现动态分配和回收。

### CXL 是什么：30 秒概要

一句话定义：CXL 是让所有计算单元（CPU、GPU、加速器）与内存进行 cache-coherent 连接的互连标准。从 CXL 3.0 起，GPU 或加速器可以不经过 CPU、直接访问内存，或者设备之间共享内存。

**三种协议**：
- **CXL.io**：基于 PCIe 的设备发现、初始化、管理协议
- **CXL.mem**：CPU 像访问本地 DRAM 一样直接读写外部设备的内存（load/store，非网络包）
- **CXL.cache**：外部设备以 cache-coherent 方式读取 CPU 侧内存

**三种设备类型**：
- **Type 1**：无自有内存，coherent 访问 CPU 内存（SmartNIC）
- **Type 2**：有自有内存（HBM/GDDR），也能访问 CPU 内存（GPU/FPGA）
- **Type 3**：纯内存设备，CPU 将其映射到自己的地址空间 ← 当前市场最热

### CXL 现状：现实检验

CXL 是 AI 集群的主力互连吗？坦白说，不是。SemiAnalysis 在 2024 年 3 月发布了题为"CXL 在 AI 时代已死"的报告，核心论点：GPU scale-up 用 NVLink/ICI，scale-out 用 Ethernet/InfiniBand，CXL 无处插足。技术上也有依据：CXL/PCIe 是 load/store 内存访问协议，对 PHY 层错误率要求极高，FEC 用得少；而 Ethernet 是包交换网络，FEC 用得多但带宽效率更高。同等引脚数下 Ethernet 能传更多数据。

**但 2024 年后形势变了：**

1. **Microsoft Azure 实战部署**：2025 年 11 月，Azure M-series VM 搭载 Astera Labs Leo CXL 内存控制器，成为 CSP 首家 CXL 内存 preview 部署
2. **DRAM 短缺危机**：Google 和 NVIDIA 已在认真考虑 CXL 作为备选内存技术（The Information 报道）
3. **KV cache 爆炸**：70B 参数模型、128K context、batch size 32 的情况下，KV cache 超过 150GB，超出 H100 的 80GB VRAM。CXL 可将 KV cache 卸载到 pooling 内存，带来 4-5 倍成本降低，200-500 倍于 SSD 的低延迟。Marvell 内部测试：CXL pooling 使 inference throughput 提升 4.8 倍，TTFT（首 token 延迟）降低 82.7%

**结论**：CXL 的定位是"内存分层扩展的补充武器"，而非主力互连。但这个补充武器的市场规模高达数十亿美元：内存扩展市场预计从 2025 年约 13 亿美元增长至 2034 年约 118 亿美元（CAGR 28.7%）。

### 超大规模云厂商 CXL 战略

**Google**：CXL Consortium 创始成员，据报道与 Marvell 合作开发定制 CXL 方案。Google 数据中心有大量已退役的 DDR4 内存，用 CXL memory expander 将其作为 cold tier 再利用是重要场景。Marvell Structera X 2404 精准瞄准这个需求：最多 12 个 DDR4 DIMM，1.5TB 物理容量，LZ4 压缩后实效 ~3TB。

**Microsoft**：Azure 已经在 M-series VM 部署 CXL。目标是突破服务器 DIMM 槽数量限制（DDR5 × 16 槽 = 16TB 上限）。CXL memory expander 可以打破这个硬件瓶颈。
